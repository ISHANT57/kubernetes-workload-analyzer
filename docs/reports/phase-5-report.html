1. What Phase 5 was for

Phase 4 produced a findings API with no UI consumer. Phase 5 built the dashboard decided in D-002: React + Vite + TypeScript, built to static files served by the Go backend itself (no Node server at runtime), uPlot for the charts that answer a specific question. Done condition (PHASES.md): Overview, Findings, Detail, Workloads, Platform Status pages.

2. Pages built

PagePurpose
Overviewtop findings, ranked health-first then resource then cost
Findingsfull filterable list (severity, category, rule)
Finding Detailfull evidence table, threshold, window, data-quality/confidence badge, caveats, and — for R001/R002 — a real uPlot usage-vs-request chart
Workloadsevery discovered workload, not only ones with findings
Platform Statusthe analyzer's own health: last run status, query errors, data coverage

uPlot is used imperatively (a ref + useEffect), not through a React wrapper component — kept as a thin, explicit integration rather than adding a charting-library dependency wrapper of its own.

3. Sticky-on-failure polling

src/hooks/usePolling.ts keeps the last-good data on screen and marks it partial/stale rather than blanking the UI on a transient API failure — the same sticky-snapshot pattern already used on the backend (Phase 3's runner, Phase 4's findings), now carried into the frontend so a brief Prometheus or network hiccup does not flash the dashboard empty.

4. New backend surface: /api/timeseries

The only backend change in this phase: GET /api/timeseries, reusing the evidence builder's existing, fixed, parameterized Prometheus queries (CPUUsageSeries/ MemoryUsageSeries in internal/evidence/builder.go) — the browser still never sends PromQL, only namespace/workload/container/ metric/window query parameters. Response shape: {"points": [{"t": unix_seconds, "v": value}, ...]}.

5. Single-binary serving

The Go backend now also serves the built frontend directly: STATIC_DIR env var + SPA fallback (internal/httpserver's spaHandler), so the whole product is one deployable binary with no separate Node server at runtime — the tradeoff D-002 was decided around. Without STATIC_DIR the backend still works as an API-only server, used during frontend development where npm run dev proxies to it instead.

6. TypeScript build issues found and fixed

Constructor parameter-property shorthand rejected. erasableSyntaxOnly disallows constructor(public status: number); ApiError was rewritten with an explicit field plus a constructor body.
Unused parameter build error. noUnusedParameters caught an unused metric parameter in formatEvidenceValue(); removed.

7. Live Playwright verification

Verified with a real backend and real cluster data via Playwright browser automation, not just built and assumed to work:

  • Desktop viewport — zero console errors.
  • Mobile viewport (390×844) — zero console errors.
  • Dark mode (prefers-color-scheme emulation) — zero console errors.

8. A real mobile CSS bug found and fixed

Long PromQL query text in the evidence table overflowed the card layout at 390px width — only visible by actually rendering the page at mobile size, not from reading the code. Fixed with word-break: break-all on .evidence-table code and overflow-x: auto on .card, then re-verified at 390px with a fresh screenshot.
